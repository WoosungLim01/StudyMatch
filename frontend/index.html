StudyMatch Pipeline (§3)
Step 1
Preference Survey
18 items, 6-point Likert scale, ~half reverse-coded. ~5 min. NOT binary/forced-choice (avoids ipsative data problem).
↓
Step 2
score_axis() + Consistency Check
Reverse-code flagged items (7 − raw). Average per axis → continuous vector in [1,6]. Flag straight-liners (SD < 0.75) and reverse-inconsistent responses.
↓
Step 3
GMM Clustering
sklearn GaussianMixture. k discovered via BIC + silhouette — NOT hard-coded. This is the key difference from MBTI's theory-first fixed axes.
↓
Step 4
predict_proba() → BRANCH
Soft membership probabilities are computed. The pipeline forks into two paths that must never merge.
4a — Display Layer
Archetype Label + Strength %
e.g. "72% Dedicated Planner". Used ONLY for UX display and shareable result. Never passed to step 5.
|
4b — Matching Layer
Raw Continuous Vector
The actual 6-axis float vector from step 2. This is the ONLY input to step 5. Collapsing it to a label would lose information.
Step 5
Pairwise Compatibility Score
Weighted similarity over axes (OkCupid-style). Motivation axis has highest weight (quasi-mandatory). Input: raw vectors only (4b).
↓
Step 6
ILP Group Formation (OR-Tools CP-SAT)
Maximize Σ compat(i,j) for pairs in same group. Each student in exactly 1 group. Group size ∈ {4,5}. NO inter-group fairness — intentional (§6/7).
Step 7 — TODO (stretch goal)
Feedback Loop
Pulse surveys → Beta-Binomial update of archetype-pair compat matrix → informs next matching cycle. Not v1.
Design Decisions
DecisionChoiceWhy
Response formatLikert 6-ptNot binary — avoids ipsative data; MBTI binary has poor test-retest reliability
Archetype axesDiscovered via GMMData-first; avoids MBTI's theory-first empirically-shaky axes
Matching philosophyHomogeneousOpt-in app — students want people like them, not mandatory group fairness
Inter-group fairnessNot optimizedWould work against the product goal; tracked as outcome metric instead
AlgorithmILP over GAProvable optimum, reproducible, scope fits exact solvers
Label vs vector separationLabel = UX only; vector = matchingPrevents information loss from collapsing continuous signal
DemographicsMetadata onlyNever in matching math — avoids sensitive-attribute-driven matching
Known Limitation — Echo Chamber Effect (§7)

Homogeneous matching may widen the gap between high-motivation and low-motivation cohorts over time: high performers keep grouping with other high performers, and vice versa. This is an accepted tradeoff of the opt-in product philosophy, not a bug. Track it as an outcome metric during beta (do archetype groups show diverging performance/retention over the semester?) rather than constraining the algorithm to prevent it.
